## Ronin Competitive Matrix — Terminal Coding Agents & Adjacent Ecosystem (P1)

Scope: 11 named tools plus one category (OSS agent frameworks + MCP). All benchmark, adoption, and pricing figures below are **vendor-, registry-, or third-party-reported** and were not independently verified. **No head-to-head measurement between Ronin and any tool exists in either direction**, so every "where Ronin leads" claim is *feature-present-and-plausible*, never *measured-to-beat*. Dimensions: License, Free + Local/BYO, MCP/Plugins, Approvals model, Model routing, Standout, Key weakness, and the honest lane where Ronin's stated design (MIT, 7-package Python uv workspace, terminal-native TUI, provider-agnostic + free-first + local/BYO, built-in fail-closed approval gate) is a structural differentiator.

### Per-tool notes

**Claude Code** — The maturity benchmark for the whole category and the sharpest philosophical opposite of Ronin: proprietary/closed, Anthropic-only, no free tier, no local. It leads on ecosystem depth (plugin marketplaces, nested subagents, Skills, hooks, context-editing) and on frontier model quality (SWE-bench figures are vendor-reported and version-noisy). Ronin's honest, feature-present contrasts are exactly the axes Claude Code forecloses: MIT/forkable, $0 default, provider-agnostic + local/BYO, and core-source extensibility beyond the sanctioned plugin API.

**Gemini CLI** — Apache-2.0, vendor-backed, 1M context, native Search grounding, real sandboxing and checkpoint+restore, huge stars. But it is Gemini-cloud-only and Google is winding down the free/consumer hosted path (June 18 2026) toward the closed Antigravity CLI. That deprecation event is the concrete illustration of Ronin's structural pitch: a provider-agnostic, free-first, local/BYO agent isn't hostage to one vendor's auth, quota, or roadmap.

**OpenAI Codex CLI** — Arguably the most resourced first-party stack (GPT-5.x-Codex, ChatGPT sign-in, cloud delegation, IDE + iOS, OS-kernel-enforced sandboxing, ~97k stars). Provider-agnostic in principle but OpenAI-first in practice, with local narrowed to a Responses-API-only wire since Feb 2026 and a Rust monolith that's harder for a Python shop to fork. Ronin's plausible lanes: no account gravity, MIT permissiveness, and a modular Python uv workspace.

**Aider** — Mature, beloved, and genuinely strong on the diff/edit engine (multi-format + Architect/Editor), Git-native atomic commits, and its own polyglot leaderboard (vendor-reported, model-level). Its clear gaps — **no native MCP**, no plugin system, no TUI/dashboard, coarse auto-apply+auto-commit approval — are precisely where Ronin claims feature-present capabilities (native MCP, TUI, explicit gate). This is one of Ronin's cleaner honest-feature contrasts.

**Continue** — Distinctive on role-based routing and "Continuous AI" markdown CI-check agents (a verification capability Ronin doesn't claim). But the flagship OSS coding-agent monorepo went **read-only** at a "final" v2.0.0 and the company pivoted to a hosted CI/Hub SaaS, and reviews flag weaker long-horizon agent behavior. Ronin's plausible lane is continuity: one actively-maintained terminal-native codebase whose core loop needs no cloud/CI control plane. Confidence medium given the fast-moving maintenance picture.

**Cline** — One shared agent core across five surfaces with a built-in MCP Marketplace and fine-grained shadow-git checkpoints; broad provider list; big (vendor-reported) adoption. Not fully open (closed JetBrains plugin + hosted-provider nudge), and the terminal CLI is the newest surface on a sidebar-first codebase. Ronin's honest contrasts are narrow: fully MIT/100% open, terminal-first, free-first as default rather than an on-ramp. Provider-agnostic and local support are parity. Confidence medium.

**Goose (Block)** — Free, local-capable, MCP-native at its core, with reproducible YAML "Recipes," an LLM-classifier SmartApprove permission mode, native subagents, and Linux-Foundation governance. It leads with a desktop GUI and a lighter REPL, and spreads across coding + research + writing + automation. Ronin's plausible lanes: terminal/TUI-first focus, coding specialization, and Python-uv hackability vs a Rust monolith.

**OpenHands** — The most research-forward: an arxiv-published, event-sourced Software Agent SDK with deterministic replay and an Agent Canvas that can orchestrate other agents over ACP; MIT core; ~80k stars; vendor-reported SWE-bench. Trade-offs: a Docker/K8s runtime, a CLI now marked "legacy" in favor of the browser Canvas, and best numbers riding frontier proprietary models. Ronin's plausible lanes: terminal-native as first-class, no mandatory Docker, uniform MIT with no source-available carve-out and no paid-cloud tilt.

**OpenCode (sst)** — Provider-agnostic client/server design with the broadest client surface (TUI + desktop + IDE + web + mobile), 75+ providers, the most mature remote-MCP story (auto-OAuth + Dynamic Client Registration), a plugin SDK, and LSP. It leads on nearly every axis. Ronin's honest lanes are narrow: a single-language Python uv workspace (simpler end-to-end self-host for a Python shop) and free-first without a curated paid tier (Zen) in the default path. Note: there is no built-in verify/self-correct loop — quality rides the plugged-in model.

**Cursor (Anysphere)** — The strongest GUI-first product: its own Composer model, up-to-8 parallel agents with best-of-N, at-scale semantic indexing (272k context), native browser self-verification, cloud/background agents, iOS, enterprise certs. It is proprietary, cloud-dependent, not truly free or local (Tab/Composer are Cursor-hosted), and its CLI is explicitly a *complement* to the IDE. This gives Ronin its widest set of feature-present contrasts: MIT, $0 default, full-loop local/BYO, terminal-native as the primary interface, and no account/cloud/data-egress requirement.

**Roo Code** — Capable pre-shutdown (Orchestrator/Boomerang decomposition, embeddings+Qdrant semantic indexing, rich in-editor GUI), but the extension was **discontinued and the repo archived read-only (2026-05-15)** with users redirected to ZooCode/Cline. It is also VS-Code-bound with no headless/CI mode. Ronin's most defensible contrast here is simply being live and maintained, plus terminal-native/editor-independent operation.

**OSS frameworks + MCP (LangGraph / CrewAI / MCP)** — Not rivals but foundation. As SDKs they lack a terminal coding loop, repo-aware diff/edit, and a default file/shell approval gate — all of which Ronin ships as a finished product. Their decisive advantage is ecosystem: MCP is the near-universal tool standard (registry counts and download figures are registry/vendor-reported), so being a first-class MCP client inherits thousands of integrations. The strategic read: Ronin should *stand on* this layer (consume MCP servers; optionally embed an orchestration lib) rather than compete with it.
