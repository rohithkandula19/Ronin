# Ronin v1.0.0

**Package version:** `1.0.0` (PEP 440) · **displays / tag:** `v1.0.0`.

The 1.0.0 line is `v1.0.0-rc.3` plus two release-readiness fixes. It is the first
non-prerelease of Ronin: a masterless, terminal-native, provider-agnostic coding
agent that reads, edits, and runs your code, with every write and shell command
behind an approval gate.

## What's in 1.0.0

Everything validated across the RC series, carried forward:

**Safety & security**
- Approval gate on every write and shell command; read operations run freely.
- Destructive-command floor (enforced even under `--yolo` / god-mode): `rm -rf`,
  force-push, `mkfs`, `dd`, fork bombs, `DROP TABLE`, **and** `git reset --hard`
  / forced `git clean` (any flag order). Branch switches and dry-runs are not
  flagged; god-mode cannot bypass the floor.
- Fail-closed cost budget: an unknown model's pricing is `UNKNOWN`, never a
  silent `$0`, so a spend cap can't be bypassed.
- Relay path-traversal confinement; prompt-injection scanning; secrets stay in a
  gitignored local config and are redacted from traces.

**Honesty**
- `ronin eval run` skips with a reason (no fake score) when auth is missing, and
  errors gracefully on a missing dataset; a deterministic offline FakeProvider
  eval path runs at `$0`.
- `ronin doctor --check` exits non-zero when it cannot verify the provider.
- No coding-quality benchmark or SWE-bench score is published — Ronin ships the
  eval harness, not a number. No claim of superiority over any other tool.

**Packaging & install**
- Standalone install proven: `ronin-cli` installs in a clean environment outside
  the repo from the built wheel set (`scripts/test_clean_install.sh`, run in CI).

## Install

- From the tag: `curl -sSL …/install.sh | bash -s -- --ref v1.0.0`.
- Standalone from the wheel set: `uv build --all-packages` then
  `pip install --find-links dist/ ronin-cli` in a clean environment.
- **`pip install ronin-cli` from PyPI is NOT yet available** — publishing the
  packages is a separate, gated step. Do not assume PyPI availability.

## Honest limitations

- **Not** independently benchmarked; **not** claimed as production-hardened or
  battle-tested. It is a 1.0.0 in the semantic-versioning sense (a stable public
  API surface for the CLI), not a statement about scale or adoption.
- **No PyPI publish** ships with this release.
- Runtime + clean-install validation was done on **macOS (arm64, Python 3.14)**,
  **CI Ubuntu**, and **Docker Ubuntu (arm64, Python 3.12)**. Native/x86 Linux and
  broad multi-distro coverage are **not** claimed.
- Full test suite: **3355 passed, 0 failed** at the release commit. The suite is
  offline and deterministic (FakeProvider); it is a correctness gate, not a
  measure of real-world coding quality.
